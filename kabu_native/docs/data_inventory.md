## 今後の蓄積方針

1. **EOD 保存（推奨・短期）**  
   - 旧系: `python yahoo_kabu_watch.py --save-intraday-1m-eod`  
   - 保存先を `kabu_native/data/intraday_1m/YYYY-MM-DD/<symbol>.csv` に寄せていく（旧系は参照のみ維持可）

2. **リプレイ用の正**  
   - ファイル名: `<code>.T.csv`（例: `9984.T.csv`）  
   - 列: `timestamp_utc`, `open`, `high`, `low`, `close`, `volume`

3. **PUSH JSONL（中期）**  
   - 場中に `kabu_native/data/push_jsonl/` へ追記  
   - リプレイは合成 board ではなく実 PUSH へ移行（Phase 4 拡張）

4. **定期監査**  
   - `python kabu_native/scripts/audit_intraday_data.py` を週次または EOD 後に実行

## kabuステーション API と過去1分足

kabuステーション® API の **板（/board）・PUSH** は **当日のスナップショット／ストリーム** が中心で、**数週間前の1分足 OHLCV を銘柄×日付で一括取得する公式手段はない** 前提で設計する（`docs/kabu_signal_design.md` Phase 5A も同趣旨）。

| 手段 | 内容 |
|------|------|
| **Yahoo 1分足 CSV** | 現リポジトリの主データ。非公式 API・約30日窓。リプレイは合成 kabu board に変換 |
| **自前蓄積 PUSH JSONL** | ライブ運用で品質は高いが履歴は積み上げのみ |
| **kabu 分足 API** | 商品・権限により異なる。本プロジェクトでは未採用。採用時は別ドキュメント化 |

**代替の現実解:** 当面は **Yahoo EOD 保存 + audit** でリプレイ母集団を増やし、kabu ネイティブ検証は **PUSH 蓄積が溜まってから** 切り替える。
